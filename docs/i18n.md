# Internationalization

The public site is served in two languages:

- **Arabic, right to left**, at the site root: `/`, `/about`, `/article/<slug>`.
- **English, left to right**, under `/en`: `/en/`, `/en/about`, `/en/article/<slug>`.

The dashboard at `/admin` stays Arabic and RTL. It gains an optional English input next to each
Arabic content field.

Read this before adding a public page, a piece of interface copy, or an editable field.

## Routing: one view, two thin routes

Astro's built-in routing is configured in [astro.config.mjs](../astro.config.mjs) as
`locales: ['ar', 'en']` with `prefixDefaultLocale: false`.

Each public page's markup lives once, in [src/views/](../src/views/). Two route files render
it, and each is a few lines long:

```
src/pages/about.astro     ─┐
src/pages/en/about.astro  ─┴─>  src/views/About.astro
```

- **Language comes from the URL.** Views and shared components call
  `localeOfPath(Astro.url.pathname)` from
  [src/lib/i18n/locale.ts](../src/lib/i18n/locale.ts), not `Astro.currentLocale`. That way a
  404 rewrite and an unmatched `/en/...` path resolve the same way as a normal page.
- **Dynamic routes resolve their own slug.** A component cannot return a `Response`, so the
  route looks up the row and rewrites a miss before rendering the view. It rewrites to `/404`,
  or to `/en/404` under `/en`. The view receives the row as a prop, and
  [NotFound.astro](../src/views/NotFound.astro) sets the 404 status itself.
- **`login` and `forgot-password` are Arabic only.** They front the Arabic dashboard, so they
  have no `/en` twin. They pass `localized={false}` to `Layout`, which drops the hreflang
  alternates; their language switcher leads to the English home page.
- **Adding a page means three files:** the view, `src/pages/<name>.astro`, and
  `src/pages/en/<name>.astro`.

[Layout.astro](../src/layouts/Layout.astro) sets `<html lang dir>` and the `hreflang`
alternates. The language switch (`.lang-switch`, styled in the vendored `style.css`) sits in
[SiteHeader.astro](../src/components/SiteHeader.astro) and keeps the visitor on the same page.

## Links

Every on-site `href` a public page renders goes through `localizePath(href, locale)`, or
`L.href(...)` in a view. That covers literal hrefs, hrefs stored in the CMS, and links inside
legal prose.

`localizePath` leaves these alone, so it is safe on any value:

- anchors, `mailto:` and external URLs
- uploaded images (`/media/<hash>`) and static assets
- `/admin` and the Arabic-only auth pages

CMS hrefs are therefore stored once, unprefixed (`/members`), and serve both languages.

## Interface copy

Fixed copy that the CMS does not own lives in [src/lib/i18n/ui.ts](../src/lib/i18n/ui.ts):
navigation, form labels, page headings, breadcrumbs, aria-labels. The Arabic object is the
source of truth, and the English one is typed against it, so a key missing from either side
fails `npx astro check`.

Form `<option>` values stay the Arabic labels in both languages, so a future form backend
receives one vocabulary. Only the visible label is translated.

## Content: `xAr` and `xEn`

Every editable Arabic field has an optional English sibling with the same name and an `En`
suffix: `headingAr`/`headingEn`, and `bodyAr1`/`bodyEn1`. Structure is shared: list items,
hrefs, images and ordering exist once, so the two languages cannot drift apart.

- **Singletons.** The English field is `enText(max)` from
  [fields.ts](../src/lib/content/schemas/fields.ts): trimmed, possibly empty, with the same
  `max` as the Arabic field. Every singleton got a version bump whose migration is
  [addEnFields](../src/lib/content/schemas/add-en-fields.ts), which adds `xEn: ''` beside each
  `xAr`.
- **Collections.** Each `*_ar` column has a `*_en` column (`NOT NULL DEFAULT ''`), and the
  input validators in [repo.ts](../src/lib/content/repo.ts) default each English field to `''`.
  Exports written before English existed, including
  [content/seed.json](../content/seed.json), therefore import unchanged.
  - JSON sub-lists (`stats`, `recs`, `blocks`) may hold older items without the `En` keys, so
    those keys are optional in the stored type.
  - Article tags are two independent lists. `tagsEn` is either empty or has one entry per
    Arabic tag.
- **Media.** `alt_en` is optional next to the required `alt_ar`.

An empty English value means "not translated yet".
[src/lib/i18n/pick.ts](../src/lib/i18n/pick.ts) decides what to render:

```astro
---
const L = localizer(localeOfPath(Astro.url.pathname));
---
<h2 class="h-section" {...L.attrs(banner, 'heading')}>{L.text(banner, 'heading')}</h2>
```

- `L.text(obj, 'heading')` returns `headingEn` on the English site when it is filled in, and
  `headingAr` otherwise.
- `L.attrs(obj, 'heading')` returns `{ lang: 'ar', dir: 'rtl' }` when that fallback happens.
  Spread it onto the mockup's own element, never onto a wrapper, so the markup stays verbatim.
- For attribute values (`alt`, `<title>`, `content`), use `L.text` alone.
- For fields whose names do not fit the helper (`bodyAr1`) or that may be missing (JSON
  sub-items), use `pick` and `fallbackAttrs` directly.

### Adding a field

1. Add `xAr` and `xEn`. For a singleton, add them in a new schema version: bump `version`,
   append a migration, and put `xEn: ''` in `initial`. For a collection, add both columns, run
   `npm run db:generate`, and add `xEn: enText(max).default('')` to the input validator.
2. In the editor, use `BilingualTextField` or `BilingualTextAreaField` from
   [BilingualFields.tsx](../src/components/admin/fields/BilingualFields.tsx). It renders the
   required Arabic input and the optional LTR English input under one label.
3. In the view, render the field with `L.text` and `L.attrs`.

## Styling

`public/mockup/style.css` was written left to right, and its `31. RTL` section re-applies right
to left under `[dir="rtl"]`, so English pages render from the same markup with no new CSS. The
vendored `main.js` also reads `document.documentElement.dir` for sliders, arrow keys and the
marquee.

Only two rules were added, both in
[overrides.css](../src/styles/mockup/overrides.css). They target Arabic fallback text inside an
English page:

- They drop the Latin letter-spacing and uppercase.
- They align the block with the page (`text-align: match-parent`), so a half-translated page
  still looks laid out.

Any other LTR-only fix belongs in `overrides.css` too, under `[dir="ltr"]`. Never edit
`style.css`.

The brand fonts (IBM Plex Sans Arabic and Tajawal) ship Latin subsets, so English needs no
extra font.
